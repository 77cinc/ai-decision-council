# 智囊团·明朝内阁制 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 65 个 perspective skills 基础上，搭建明朝内阁制协作系统，让多位谋士能共同议事、由主公决策、并保留完整历史记录（丝纶簿）。

**Architecture:** 明朝内阁制的四大机制落地为四个产物：①内阁召集官 skill（council， orchestrator）②缙绅录（council-registry，65 位谋士花名册）③丝纶簿档案库（智囊团议事录/）④示例存档（000-示例议事.md）。council skill 读取 registry 和 INDEX.md，按"廷推→议事→票拟→呈主→存档"流程运行，输出明朝风格的票拟式报告。

**Tech Stack:** Claude Code skill 系统（SKILL.md 格式）+ Markdown 文件存档

**Spec source:** 基于主公与谋士的 brainstorming 讨论产出

## Global Constraints

- 每次议事的存档命名：`YYYY-MM-DD-<问题概述缩写>.md`（问题概述 10 字以内）
- 输出必须使用"票拟-批红"格式，谋士不可替主公决策
- 给事中环节不可省略（即使只有 1 位给事中）
- 语气：谋士称"臣"，用户称"主公"，结尾"臣等谨请圣裁"

## 📜 票拟

**臣马云（首辅）谨奏：**

臣等窃闻敌降价之事，不可盲从，亦不可轻忽。综合诸位所见，谨呈二策。

### 议事纪要

**马云（开场）**：我经历过无数次价格战。淘宝打易趣的时候，eBay 说要用钱砸死我们——结果呢？价格战这个东西，**你跟着打，你就输了**。客户要的不是便宜，是**占便宜的感觉**。你给他一个"贵得值"的理由，他比谁都忠诚。

**诸葛亮（回应）**：马总所言，臣深以为然。然臣补一言——"善战者致人，不致于人"，价格战之要，不在 price，在 **position**。当守中寓攻：差异化守住核心阵地，局部反击试探对手虚实。

**马斯克（重构问题）**：你们都在讨论"怎么打赢价格战"，但我想问——**为什么还要做现在这个产品？** 用第一性原理拆解——如果从零开始设计，你会做成现在这样吗？如果不会，那对手降不降价根本不重要，因为你们都在解决一个**错误的问题**。

### 臣等共识

- 全体反对盲目跟进降价
- 一致认为应先评估自身核心优势
- 均认可长期价值 > 短期份额

### 📜 分歧点

- **差异化 vs 重构**：诸葛亮主差异化突围，马斯克主第一性原理重构

### 🎯 备选方案

| 选项 | 主倡 | 核心理由 | 风险 | 预期收益 |
|-----|------|---------|------|---------|
| **甲策：差异化突围** | 马云、诸葛亮 | 重构价值感知，让对手降价失效 | 需时间沉淀 | 高（长期） |
| **乙策：第一性原理重构** | 马斯克 | 重新定义产品，让降价变得无关紧要 | 需颠覆性创新 | 高（长期） |

## 🏛 廷推算法（自动选谋士）

**目的**：从缙绅录 65 位谋士中，为本次议题选出最合适的 5-7 位入阁。

**算法步骤**：

1. **读取缙绅录**：`./.claude/skills/council-registry/SKILL.md`
2. **对每位谋士评估"议题相关度"**（1-10 分），基于：
   - 谋士的"核心标签"与议题关键词的匹配度
   - 谋士的"候选角色"（首辅/次辅候选人优先）
3. **必选约束**：
   - 至少 1 位"首辅候选"或"次辅候选"（作为首辅）
   - 至少 1 位"给事中候选"（作为六科给事中）
   - 视角多样性：入选谋士不能全属同一领域（如不能全是战略/军事）
4. **选 Top 5-7**：按相关度排序，取前 5-7 位
5. **公示廷推结果**：向主公展示入选名单 + 每位入选理由（1-2 句）

**若主公钦点谋士**：
- 使用主公指定的谋士
- 仍需从给事中候选池中选 1 位给事中（若主公未指定）
- 若主公指定了给事中人选，按主公指定的来

## 🗣 议事流程（圆桌接力制）

### Phase 1: 首辅开场

- 首辅先发言（1-2 段），定调整个议题的分析框架
- 引用丝纶簿历史（如有）
- 点出关键问题："此局关键在于……"

### Phase 2: 群辅依次发言

- 每位群辅按角色顺序发言
- **强制规则**：每位必须回应前一位的至少一个要点（赞同/修正/反驳）
- 可引用丝纶簿："臣查丝纶簿第 XX 号，上次主公遇类似问题，臣曾言……"
- 每位发言控制在 1-3 段

### Phase 3: 六科给事中封驳

- 给事中在**末位集中发言**（不插在中间）
- 职责：质疑主流意见、挑逻辑漏洞、指出被忽视的风险
- 可质疑任何一位谋士的观点
- 语气可以更尖锐（"臣不敢苟同"、"臣请主公三思"）

### Phase 4: 首辅综合

- 首辅综合所有发言，形成最终票拟
- 明确列出"臣等共识"与"分歧点"
- 提出 1-3 个备选方案（甲策/乙策/丙策），每个方案标注主倡谋士

| **自动廷推** | 不指定谋士时，自动选 5-7 位 + 公示理由 |
| **钦点模式** | 指定谋士名时，使用指定谋士 + 自动配给事中 |
| **议事格式** | 输出包含：廷推名单、议事纪要、共识、分歧、备选方案、给事中封驳、请圣裁 |
| **自动存档** | 每次议事生成存档文件 + 追加 INDEX.md |
| **跨会话检索** | 第二次议事时，开场引用第一次的相关立场 |
| **命名规范** | 存档文件名格式：`YYYY-MM-DD-<问题概述>.md` |
| **语气礼仪** | 输出用"主公/臣/谨请圣裁"等明朝风格 |
| **禁忌遵守** | 不可替主公决策；给事中环节不可省略 |
